\section{内存布局}
\label{sec:memlayout}

这个 OS 的 \textit{Load Memory Address} (LMA) 如下图所示。这是它们被加载到硬件上时的物理内存位置，但并非虚拟内存位置。换句话说，虚拟内存位置 (VMA) 是给链接器看的，而 LMA 则是给加载器看的。

其中，pt\_root 是页表的根。这个内存布局要求可以由链接器脚本 link.ld 完成。

从虚拟内存的角度而言，.text.low、pt\_root 以及 a0 与 a1 的 VMA 就等于它们的 LMA。其余部分的 VMA 都是 LMA 增加一个特定的偏移量 0xffff'ffc0'0000'0000 所得到的。这主要是因为 RISC-V 指令集\cite{rvPrivManual}的要求。

我采用的 Sv39 页表有 39 位的虚拟地址，但是放入的是 64 位寄存器。RISC-V 要求前 25 位必须 sign-extend，因此虚拟地址空间被强制分为了两部分。这个 OS 将会占据较高的半部分虚拟地址，而 user-space 程序将会使用较低的一半。上面的偏移量的前 26 位是 1，正是这个原因。

实际上，链接器——至少 GNU 的 ld——会将 VMA 按照 8-byte 对齐，但却不会对 LMA 这么做。这会导致一些让人摸不着头脑的 bug，因此我们需要在链接器脚本里通过 VMA 计算 LMA，而不是反过来。

\section{启动}
\label{sec:boot}

在启动时，我决定立即启用虚拟内存，而不先进行其他任何设置。甚至寄存器 sp 都没有被设置，因此栈也暂时无法使用。启动时的 a0 和 a1 是 hart id 和 FDT (\textit{flattened device tree}) 的地址，也需要顺手保存到上面图中的位置。

我先按照偏移量，开 16 个 1 GB 的页，将前 16 GB 物理内存映射至对应的虚拟地址。（QEMU 本身只有 128 MB 的物理内存，虽然理论而言这读了设备树才能知道。）接下来，我将第 8 GB 恒等映射，然后启用页表。这个恒等映射是必要的，不然启用页表后的下一条指令将会立即 page-fault。之后我会把它移除。

接下来，OS 将会跳转到真正的 .text 段开始执行。普通的 jal 是不可以的，因为指令集编码限制，它只支持 20 位的跳转，而我的跨度有 64 位那么大。同样地，la 也是不可以的——它实际上是 auipc，也只支持 20 位范围内的寻址。因此，我只能将高段的 .text 固定下来，让它留在 0x8020'3000 的位置。

接下来，我会启动一个 free-list allocator。它是一个物理内存分配器，而且只管理 16 MB 内存。这是为了让大部分 C++ 容器可以使用，可见 \cref{sec:container}。虚拟内存分配器是基于 bitmap 的，在最开始就放在 .bss 段，初始化为全零。理论上来说，当物理内存分配器好了之后，这个虚拟内存分配器就可以工作了。

但是，虚拟内存需要操纵页表，而操纵页表的代码几乎都默认页表的根是当前进程的 PCB 里所记载的那个：详见\cref{sec:pcb}。然而，PCB 中含有一个 \cpp{os::vector<vma>}，所以构造它需要分配虚拟内存。我有两个选择：将这个 vector 改为 intrusive\_list，或是增加一个 onboot 全局变量，对最开始的分配进行特殊处理。我选择了后者，因为 vma 这种小结构体如果加入两个指针会变为原来的两倍大，而增加一个（几乎不会分支预测出错的）onboot 判断应当是没有什么影响的，尽管我没有测试过这个断言。此外，onboot 还有望在其他遇到类似困境的地方发挥作用。

在初始的分配器启动完成之后，我将启动 PLIC，接受硬件中断。不过这需要分为几步。

首先，当然需要读取 FDT，看看究竟有哪些硬件。读完之后，立即启用 UART 中断 (\#10)，以便后续调试，比如按下 Ctrl+C 退出之类的。接下来，理论上可以开始探测其他的硬件了，然后将它们放进 devfs 里——但是这个文件系统还没有 mount。

因此，我们需要先 mount。我选择 mount 这三个文件系统：initramfs, tmpfs 和 devfs。这里的 initramfs 目前还是仅作调试用的。同时，记录一下支持的文件系统和 mount 它们的方式（\cref{sec:vfs}）。

在 mount 完成之后，就可以开始沟通硬件。VirtIO 驱动（\cref{sec:virtio}）将会根据 FDT 的指示，在合适的位置尝试沟通。

一切准备就绪，我们可以加载第一个 user-space 程序了。初始化调度器（\cref{sec:scheduler}），然后启动 timer interrupt，通过 ELF loader 读取并加载 initramfs 中的 /init。同时，顺便加入一个 idle 进程，它处于 kernel-space。至此，启动结束。
