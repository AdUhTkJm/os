\section{与汇编的交流}

众所周知，只要使用 \cpp{extern "C"}, 就可以将 C++ 函数当做 C 链接。但有的时候，我们必须让编译器进行 name-mangling，比如要调用某个重载的时候。好在它的规则并不复杂，只是初看吓人而已。具体的规则可以参见 Itanium C++ ABI \cite{itanium}, Section 5.1。如果熟悉 clang （前端）的内部实现，那么对它应该不会陌生。

举个例子，如\cref{sec:interrupt}所述，在 interruption handler 中，我们会加载 ksp。在汇编中，我们有如下代码：
\begin{minted}{asm}
stvec_pos:
  # Record current sp.
  csrw sscratch, sp
  
  # Load the ksp of the process.
  la sp, _ZN2os9schedulerE # os::scheduler
  ld sp, 48(sp)            # scheduler_t::active
  ld sp, 32(sp)            # pcb_t::ksp

  # Save registers to the kernel stack.
  sd ra, 0(sp)

  ...
\end{minted}

其中的 \_ZN2os9schedulerE 就是全局变量 os::scheduler 的符号名称，而后面的两条指令则是在加载它的成员变量。我们可以使用 \cpp{static_assert} 来保证偏移量正确。

\subsection{SSO}

我实现了 SSO (\textit{short string optimization})，它可以减少 string 的动态内存分配。在 24 bytes 以内（不包含）的字符串都将被分配在栈上，而不是堆上。由于整个 OS 中，string 大量被默认构造（例如 vector<string>, hashmap<string, ...>），这减少的分配量是十分可观的。

\section{RTTI}
\label{sec:rtti}

在 VFS 的实现中，我们可能会用到 \cpp{dynamic_cast}，主要是为了访问子类独有的数据。对于单继承而言，指向子类的指针和指向父类的指针应该是一致的，所以我们可以直接对同一个指针进行强制类型转换。

为了验证这个转换是否正确，我们确实需要一个类似 RTTI (\textit{runtime type info}) 的信息。我采取的或许不是最漂亮的方法，不过至少能用。

\begin{minted}{cpp}
template<class T>
class inode_impl : public inode {
  static const void *class_id() {
    static int unique;
    return &unique;
  }
public:
  inode_impl(class fs *fs, int uid, int gid): inode(fs, uid, gid, (long) class_id()) {}
  static bool classof(inode *p) {
    return p->rtti == (long) class_id();
  }
};
\end{minted}

我们要求每个 inode 的子类 T 都继承 inode\_impl<T>，而对应的类型信息 ID 则由 T 决定。这种“重复自身的模板”方式被称为 CRTP (\textit{curious recursive template pattern})。

LLVM 也禁用了 RTTI，因此它也有相似的内容。依靠这个 RTTI 信息，我们很容易实现自己的 \cpp{dyn_cast}, \cpp{cast} 和 \cpp{isa}。
